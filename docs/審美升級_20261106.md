## 0. Design Read

**Reading this as: 一個「假裝成 AI 編碼工具」的長篇閱讀器，給一個每天在辦公室用 VS Code 的人，語言是工具的中性灰＋等寬節奏，方向是 DSH 真值的復刻——所以美感只能來自紀律（階梯、對齊、留白、克制），不能來自新裝飾。**

## 1. 三個旋鈕

| 旋鈕 | 值 | 為什麼是這個數字，不是別的 |
|---|---|---|
| **VARIANCE 2** | 幾近對稱 | 這是三欄工具殼，不是 landing page。任何「不對稱構圖」都會立刻出戲——真工具的工作區就是一張固定網格。留給美感的地方只有一處：正文欄的留白比例。 |
| **MOTION 3** | 只做狀態回饋 | `motion.js` 已經把面板／段落／按下都包了，而且**翻頁是 `app.js:679` 逐行改 `scrollTop`**，平滑捲動會跟它打架（見 §6）。這裡再加動畫只會讓「打字機朗讀」變卡。 |

## 3. 問題清單（12 條，照嚴重度）

### 01 · 右欄和正文同一塊底色 → 這就是「看不到目錄」的第一因
- **位置** `theme.css:845` `.dsh-right{background:var(--bg)}`；左欄 `theme.css:694` 用的是 `--bg-side`（= `--dsh-color-sidebar-fill`）。
- **現在** 300px 的目錄欄底色 = 正文底色，兩者只隔一條 `.5px` 的 `line-strong`（`#ffffff29` → 對底 CR **1.63**）。左邊是面板，右邊不是。
- **為什麼醜** 左右不對稱。眼睛會把右欄讀成「正文右邊的空白」，不會讀成一份獨立清單；300px 的欄位存在感＝0。
- **怎麼改** `:root[data-shell="dsh"] .dsh-right{background:var(--dsh-color-sidebar-fill)}`（一個宣告，不碰任何尺寸）。

### 02 · 1100px 以下，目錄唯一的入口是一顆沒標籤的 16px 圖示
- **位置** `dsh-polish-2.css:147`（抽屜 `translateX(101%)`＋`visibility:hidden`）、`chrome.js:142`（`#tbList`）、`theme.css:842`（`#tocBtn` 在抽屜「裡面」）。
- **現在** <1100 時面板完全移出畫面，唯一能開的是頂欄第 4 顆圖示；四顆 16px 圖示等距、同色（`--fg3`）、只靠 `title` 提示。抽屜裡的收合鈕跟著抽屜一起被藏起來。
- **為什麼醜** 「有這個功能」和「找得到這個功能」是兩件事。820/390 兩張圖上，目錄在畫面上等於不存在。
- **怎麼改** 讓入口在窄寬度變成有底的一顆（見 CSS ②）。真正的解法是把它移出圖示群（要改 `chrome.js`，不在本文件範圍）。

### 03 · 正文欄 828 和輸入卡 680 不共軸，左緣差 55px
- **位置** `theme.css:373`（`.thread` 吃 `--dsh-content-max` 920）vs `theme.css:820`（`.composer` 吃 `--dsh-content-w` 680 + 32）。`index.json` 實測：thread `x=315 w=780`、composer `x=370 w=680`。
- **現在** 同一條垂直軸上，上面是 780 寬、下面是 680 寬；左邊差 55px、右邊差 45px。
- **為什麼醜** 這是整張圖最容易被說「沒有對齊」的地方。輸入卡因此讀起來像一塊浮在正文外面的板子，而不是這條對話的一部分。
- **怎麼改** 讓正文欄寬 = 輸入卡內寬（680）：`.thread{max-width:calc(var(--dsh-content-w,680px) + var(--dsh-card-extra,32px));padding:12px var(--dsh-clearance,16px) 8px}`。1440／1920／1024／820 四個寬度我都算過，左右緣各差 0，不產生橫向溢出。

### 04 · 頂欄標題 13px 比正文 14px 還小，且分頁左緣多縮 8px
- **位置** `dsh-polish.css:72`（`.crumb` 13px）、`theme.css:801`（`.head-tabs{padding-left:8px}`）vs `--dsh-head-pad` 的左內距 20。
- **現在** 標題 13px/400，正文 14px；兩行元素左緣一個在 20、一個在 28（同一塊頂欄裡兩條左基準）。
- **為什麼醜** 標題小於正文，就沒有「這是這一則對話的名字」的層級；而 8px 的錯位讓頂欄怎麼看都像少了對齊。
- **怎麼改** 標題 16/24/500（16 是尺度的下一階，`min-height:30` 裝得下 24 行高），`.head-tabs{padding-left:0}`。

### 05 · 小字一共 8 個值（9/10/10.5/11/11.5/12/12.5/13）擠在 9–13px
- **位置** 全站；量出來的出現次數：10.5×13、11×14、11.5×13、12×14、12.5×18、13×15、10×6、9×2。
- **現在** 光「次要資訊」就有 8 種大小，其中 11 和 12 只差 1px。
- **為什麼醜** 1px 的差看不出是「層級」，只看得出「沒對齊」。八個值等於沒有階梯，所以整片介面讀起來是糊的。
- **怎麼改** 小字一律 12/16，列級 13，正文 14（真值），標題 16，書名 18（真值）。11 全數併入 12。

### 06 · 段距 12px 配行高 24px；尾註貼上端只有 4px
- **位置** `theme.css:370`（`.p{margin-bottom:12px}`）、`dsh-polish-2.css:45`（`.meta{margin:4px 0 16px}`）。
- **現在** 段與段只隔半行；尾註（`2,045 tok · src/…`）離上一段 4px，像是被吸住。
- **為什麼醜** 中文長段落靠「段距 > 行距」才分得開。半行間距讓整章變成一塊灰磚，眼睛找不到換氣點；4px 的尾註則像掉下來的碎片。**14/24 真值不動，只動周圍留白。**
- **怎麼改** `.p{margin-bottom:16px}`、`.meta{margin:8px 0 16px}`、`.turn.user{margin:16px 0 8px}`。

### 07 · 圖示軌（56px）：主次不分，而且收合鈕被裁掉 10px
- **位置** `theme.css:875-891`（rail 規則）、`theme.css:721`（`.side-brand .ghost.icon` 28px）、`--dsh-side-pad:6px 12px` 在 rail 被改成 `18px 6px 6px`。
- **現在** rail 內容寬 = 56−12 = **44px**，但 `.side-brand` 的子元素是 18（資料夾）＋8（gap）＋28（收合鈕）= **54px**，超出的 10px 被 `overflow:hidden` 切掉 → 展開鈕只剩 18px 可點。「新對話」和另外三顆面板圖示都是 36×36、都沒有底色。
- **為什麼醜** 一個軌道上五個一模一樣的方塊，唯一「主要動作」看不出是主要；被切一半的按鈕則是「壞掉」的訊號。
- **怎麼改** 收合鈕在 rail 收成 20px（18+4+20 = 42 ≤ 44）、gap 8→4；「新對話」補回 elevated 底＋inset 細框，其餘三顆的圖示降到 `--fg3`（見 CSS ⑦）。

### 08 · 圖示粗細四種：1.6×15、1.7×6、1.8×2、2×2
- **位置** `index.html` 內嵌 `<path stroke-width>`；`icons.js:58` 產生的是 1.7。
- **現在** 同一排 16px 圖示混著 1.6 和 1.7；12px 的放大鏡用 1.8、關閉鍵用 2.0。
- **為什麼醜** 0.1 的差在 16px 上看不出是「設計」，只看得出「這兩顆好像不一樣重」；1.8 的 12px 放大鏡在 36px 的列裡比 16px 的圖示還亮。
- **怎麼改** 一個宣告收平：16px 全部 1.6，只有 12px（`.find`）給 1.8 做光學補償。CSS 蓋得過 presentation attribute，不用改任何 SVG。

### 09 · 深色裡輸入卡「沒有邊」：填色只差 1.16，陰影等於沒有
- **位置** `theme.css:823`（`.box{border:0;box-shadow:0 6px 24px rgba(0,0,0,.18);background:--dsh-color-input}`）。
- **現在** 卡片 `#2c2c2e` 對底 `#151517` = **CR 1.16**；外陰影是 .18 的黑，壓在 `#151517` 上幾乎不可見；border 是 0。28px 的大圓角失去了形狀依據。
- **為什麼醜** 圓角是用「邊」讀出來的。沒有可見的邊，28px 就只是一塊模糊的深色板；而且 `#2c2c2e` 剛好等於「選中的列」，卡片和 hover 態撞色。
- **怎麼改** 補一條 `.5px` inset 邊 + 頂部 1px 高光（`color-mix(in srgb,var(--fg) 7%)`）+ 真正的深陰影；focus 時只把邊換成 accent 40%（見 CSS ⑨，兩組 box-shadow 結構相同所以能過渡）。

### 10 · 底部一列：3 顆圖示＋1 段文字，間距 8/8/8 全部一樣
- **位置** `dsh-polish.css:378-397`（`.box-line{gap:8px}`、`#modelTag` 11px、`.hint-btn` 26px）。
- **現在** 一列裡 `>`、輸入區、`?`、`▷`、`opus 4.5 · 中`、`⏎` 六個東西等距 8px。
- **為什麼醜** 圖示之間 8px 太鬆（三顆連不成一組），文字標籤夾在圖示中間又太擠；`opus 4.5 · 中` 是全列最寬的一塊 11px 灰字，反而變成視覺重心。
- **怎麼改** 圖示群 gap 4、文字標籤左側留 8 當分隔（不用新增元素，只改間距與字級；`order` 可留著不動）。

### 11 · 狀態列 8 項同一顏色同一大小，唯一有用的資訊被稀釋
- **位置** `index.html:153-164`（8 個 `.sb-item`）、`a11y-tokens.css:173`（全部吃 `--a11y-status-fg`）。
- **現在** 1440 上 `main* / +1683 −0 / ⏱03:12 / ▍42 tok/s / 614/1359 / UTF-8 / CPU 12% / ↑8ms↓3ms` 八項同權重；章節位置只是 `--fg2` + 500。
- **為什麼醜** 偽裝用的假遙測（CPU、延遲）和真實的閱讀位置（614／1359）長得一模一樣，讀者每次都要重新找。**密度的問題不是項目多，是沒有主次。**
- **怎麼改** 章節位置拉到 `--fg` / 500，其餘降到 `--fg3`；間距由 `gap` 改成每項 `padding`（同一條 8px 網格，但讀起來是「一格格」而不是「散落的字」）。

### 12 · 同一個語意三種紅、兩種綠，加上一個不在 DSH 色票裡的琥珀
- **位置** `theme.css:205` `#c1654f`（`.del`）、`theme.css:617` `#e06c75`（`.cc-del`）、`dsh-polish-2.css:102` `#e06b6b`、`dsh-polish-3.css:63` 又是 `#e06b6b`；綠：`theme.css:346` `--ok:#4ed17e`、`theme.css:618` `#98c379`；另外 `--acc2:#f59e0b`（琥珀，DSH 真值裡沒這個色）。
- **現在** 「刪除」有三個紅、「新增」有兩個綠，琥珀色被用在工具行函式名、diff 分隔、狀態列的 `−0`。
- **為什麼醜** 這是「土」的最大單一來源：中性灰的殼裡插進三個飽和度破表的暖色，而且彼此不同源。色相一多，灰就顯髒。
- **怎麼改** 全部走 `color-mix(in srgb, 一個紅 80%, var(--fg))`：紅用 `#e06b6b`、綠用 `--ok`、琥珀只留給「警告」一個用途。CSS 覆蓋層不新增色票，只統一來源。

> 圓角一致性（沒進前 12，但一定要順手改）：`kbd` 的 **3px** 是全站唯一不在 4/8/12/16/20/28 尺度上的數字，`.pill` 的 **999px** 是全站唯一的橢圓 → `kbd{border-radius:4px}`、`.pill{border-radius:8px}`。改完圓角只剩 4（小元件）/8（鍵、膠囊）/12（列、面板）/20（使用者發言）/28（輸入卡）五階。

1. **最安全**：邊框（Δ 只有 alpha）→ 像素差幾乎為 0，先把「沒有邊」修掉。
2. **次安全**：文字三階（ΔB 最多 −23）→ 只影響文字像素。
3. **最後**：accent（dark 的 ΔB −41）→ 它出現在分頁底線、選中條、章名、連結，`vision_pixel_diff` 會抓得到；如果閘門有門檻，這一項單獨上、單獨比對。

## 6. 動效（4 條，只做有資訊的）

現況不是「缺動效」，是**時長有三套並存**（`--dsh-dur .2s`、`dsh-polish` 的 fast .1s、`motion.js` 的 120/180/220ms）。所以第一件事是收斂，不是增加。

1. **hover：統一 `--dsh-dur-fast`（100ms）。** 現況側欄列 100ms、頂欄 100ms，但 `motion.js` 用 120ms 蓋掉一部分 → 同一個 hover 在兩個區塊速度不同。`motion.js` 的規則特異性低，(0,1,0)，所以 `:root[data-shell="dsh"] .sa, :root[data-shell="dsh"] .tb-btn, :root[data-shell="dsh"] .ch{transition:background-color var(--dsh-dur-fast) var(--dsh-ease),color var(--dsh-dur-fast) var(--dsh-ease)}` 就能收平。
2. **開面板：只留一套。** 現在 `.panel` 同時吃到 `dsh-polish.css:311` 的 `polish-pop`（200ms）和 `motion.js:27` 的 `moyuFadeUp`（220ms），後者贏；兩者位移不同（−4px vs 6px）。指定一個：`:root[data-shell="dsh"] .panel:not([hidden]),:root[data-shell="dsh"] .theme-menu:not([hidden]){animation:polish-pop var(--dsh-dur) var(--dsh-ease) both}`。
3. **翻頁跟隨：不要用 `scroll-behavior:smooth`。** `app.js:679` 是逐行 `stream.scrollTop = ...` 推進的，平滑捲動會讓每一次賦值都變成一段動畫，結果是捲動追不上文字。正確做法是讓**新出現的段落**淡入（`motion.js:38` 的 `moyuPara` 已經在做，180ms / 3px，維持不動），把「跟隨感」交給捲動本身。
4. **目錄選中：160ms 的指示條。** 現況是 instant 的 `box-shadow:inset 2px 0 0`（`dsh-polish.css:239`），章節一換就「啪」地跳。要動的話：`.ch{position:relative}` ＋ `.ch.on::before{content:"";position:absolute;left:0;top:6px;bottom:6px;width:2px;border-radius:2px;background:var(--acc);transform-origin:top;animation:taste-bar 160ms var(--dsh-ease) both}` ＋ `@keyframes taste-bar{from{transform:scaleY(0)}to{transform:scaleY(1)}}`，並把 `.ch.on{box-shadow:none}`。

**reduced-motion**：`dsh-polish.css:347` 已經有一段全域 `animation-duration:.001ms` + `transition-duration:.001ms`，但它是 `[data-shell="dsh"] *`（(0,1,2)），會被 `motion.js` 的 `*` 蓋掉（同分、後者勝）。補一段同分但更晚的：

```css
@media (prefers-reduced-motion: reduce){
  :root[data-shell="dsh"] *, :root[data-shell="dsh"] *::before, :root[data-shell="dsh"] *::after{
    animation-duration:.001ms!important;animation-iteration-count:1!important;
    transition-duration:.001ms!important;scroll-behavior:auto!important;
  }
}
```

## 7. 不建議（改了會破壞偽裝）

1. **把 accent 換成暖橙（Claude `#d97757`）。** 藍色是這個殼「像工具」的最大單一訊號，換成橙就變成閱讀 App；而且 `claude-code` 主題已經演過一次。
2. **加襯線體、加書封、加頭像、加氣泡。** 產品定義直接禁止，`disguise-gate` 也會擋。
3. **在側欄或頂欄加「目錄／書架／字級」這類中文字樣。** 外殼文字不准出現書/章/目錄，黑名單會擋；窄寬度只能靠圖示與底色解決（§3-02）。
4. **用 `backdrop-filter:blur()` 做玻璃質感。** `dsh-polish.css:310` 已經在面板上加了 12px blur，在 Electron 上會讓面板拖動掉幀；DSH 真值本身也沒有玻璃。要質感用 1px 高光＋實邊，不用模糊。
5. **把正文欄拉到 920（回到 `--dsh-content-max`）。** 820 那張圖已經證明太寬；§3-03 的 680 對中文是 48 字/行，仍在可讀上限內。
