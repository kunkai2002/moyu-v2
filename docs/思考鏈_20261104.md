## 結構（和既有對話流的關係）

```
.turn.ai
  > .b
      > .think.rz  ← 這個元件（不是 .p、沒有 data-pi）
      > .pb
          > p.p[data-pi=…]
```

- 一個 `.turn.ai`（有 `.pb` 的助手回覆）＝一塊 `.think`，插在 `.pb` 前面、同一個 `.b` 裡。
  **一章被切成 1–3 段時，每一段都是新的助手回覆，各有一塊**（段與段之間本來就有一則使用者的「繼續」）。
- 絕不碰 `.p`／`data-pi`；進度、劃線、筆記的段落索引完全不受影響（測試有守）。
- 用 `turn.dataset.think` 當哨兵，`MutationObserver` 重掃不會重複插；換章／換書整串被清掉時跟著消失。
- `.turn.ai` 沒有 `.pb`（工具呼叫、錯誤、首頁）不會長出思考塊。
- 載入中的代理回覆（`.pb > .meta.loading`）不插；等真的內容到了才插。

### 為什麼 class 叫 `.think`、不是 `.rz`

`.rz` 在舊程式裡已經是**側欄拖曳柄**的 class：`ui/layout.js:41`、`ui/wiring2.js:11` 都建立 `.rz`
（注入 `position:absolute; width:6px; cursor:col-resize; background` 等），`theme.css` 也有 `.side .rz` 的規則。
第一版曾用 `.think rz` 當相容別名並在 `.turn.ai .b > .think.rz` 硬壓回去，實測會讓判定變得雙重語意
（任何未來改 `.rz` 的人都會踩到）。2026-11-04 Lead 決定：**只用 `.think`**，測試斷言一起改名。
驗收條件（task-3）原本寫的 `.rz` 請以 `.think` 為準。

## 行為規格

### 進行中

- header：spinner ＋「思考中」＋ `·` ＋ 跳秒（`0.0s` → `1.4s`…，100ms 更新一次）＋ 收合箭頭。
- 下面 2–5 行短推理，**逐行**出現；上一行真的出現後再等 **300–700ms** 放下一個
  （用「實際時間」排，不用預先算絕對時間——計時器被延遲時兩行會黏在一起，那就不像在想了）。
- 推理文字走工具語彙：上下文／稱呼／時間線／視角／語氣／標點／代名詞／伏筆／節奏／diff 改動…
  不准出現 書／章／讀／頁／目錄（外殼黑名單；測試會掃）。
- 1–2 行會**先閃**一個更短或不同措辭 200–400ms，再換成定稿。例：
  「對時間線」→「確認時間線沒有跳」、「去重…」→「把重複的句子挑掉」、
  「誰指的是誰？」→「檢查代名詞指向，別讓兩個「他」指錯人」。
  JOJO 原話：「最好思考鏈還會時不時的閃過一些類似思考的文字，讓人以為真的在思考。」
- 進行中的文字有字面掃光（shimmer，2.4s），量測用 `--dsh-dur/--dsh-ease` 與主題代幣。

### 結束

- 全長 **2–5 秒**（`wantTotal` 2.2–4.6s；最後一行定稿後再留一段，總長不超過 5s）。
- header 換成「已完成思考 · 3.2s · N tok」；spinner → 綠色勾勾；秒數是實際量到的（一位小數）。
- `N tok` 由這則回覆的正文估算（字數 × 5–7%，至少 40）——只是偽裝用的數字，不是真的 tokenizer。
- 結束後**收合成單行**（預設），點 header 展開／收合；展開喜好存 `localStorage.moyu.think.doneOpen`
  （`'1'`＝展開），下一個思考塊結束時沿用（進行中一律展開）。

### 不自動捲動

- 元件**沒有任何** `scrollTop`／`scrollIntoView`／`scrollTo` 呼叫，不碰 `#stream` 的捲動位置。
- 測試把 `#stream.scrollTop` 的 setter 包起來記：整段動畫期間 **0 次 JS 寫入**。
- 補償現象（實測）：思考行讓 block 長高時，Chromium 的 **scroll anchoring** 會自己微調 `scrollTop`
  （實測 +82～+124px），目的是讓畫面裡的參考段留在原位；測試量的是「畫面上的參考段 top 不移動（≤4px）」，
  而且「沒有任何 JS 去寫 scrollTop」。這不是元件在捲，也不是「自動接下一章」那種捲動。

### prefers-reduced-motion

- 不 shimmer、不淡入、不閃、spinner 不轉（CSS `@media` 直接關掉動畫／轉場）。
- JS 一次把 2–5 行全部顯示（直接顯示，不逐行），照樣 2–5 秒後收合成「已完成思考」。
- 測試用 `page.emulateMediaFeatures` 模擬 reduce，量 `animation-name: none`、`transition` 0、行 `opacity: 1`。

### 尺寸

`12px / 20px`（固定行高，不用比例，避免 19.8px 這種抖動值被 `tools/ui-lint.js` 判違規；
11 太小、14 會跟正文搶）。測試有斷言 `font-size:12px; line-height:20px`。

## 已知取捨

- **一章切成多段時會有多塊思考**：每段都是帶 `.pb` 的助手回覆，行為上一段一次「繼續」，各有一塊。
  如果 JOJO 只要「一章開頭一塊」，改 `scan()` 的條件即可（目前刻意照「每則回覆」）。
- **載入中（loading dots）沒有思考塊**：那則代理回覆會被 `app.js` 換掉；思考塊等下載完、真的內容出現才插。
  快取命中時幾乎無感；第一次抓章節時會先看到 loading 再看到思考塊。
- **文字是繁體、正文是簡體**：思考列屬外殼（跟 UI 一致用繁體），跟正文本來就混排；disguise-gate 只看黑名單。
- 閃字是「換文字」不是動畫；減少動態時一併關掉（避免文字跳動）。
- `row.dataset.flash` 記的是**規劃**停留毫秒（200–400），測試驗這個設計值；實際換字時間會受無頭環境的長任務
  延後（實測偶有 3xx→1005ms），但那只是把短句留久一點，不是元件排程變了。
- 測試的逐行間隔容許到 1100ms：排程本身是 300–700ms，無頭 Electron 偶爾有計時器延遲；
  用「上一行真的出現後再排下一個」的串接寫法後，實際間隔不會短於 300ms，長的那邊才是環境抖動。
