- 只讀 `ui/` 與 `docs/DSH-真值.json`，**不改任何 ui 檔**。

## 2. 為什麼一定要 `--selftest`

量測鏈是 `Electron → puppeteer → getBoundingClientRect / getComputedStyle`。
如果這條鏈自己會偏 1px，那「±2px」就是在量空氣。

`--selftest` 自己產生一張合成頁（`_probe/layout-selftest.html`），裡面是寫死的已知尺寸：

| 已知 | 值 |
|---|---|
| `#w` 寬／高 | 280 × 76 |
| `#brand` 高 | 60 |
| `#icon` | 28 × 28 |
| `#card` 圓角 | 28px |
| `#card` min-height | 36px |
| `#card` padding | 10 / 28 / 0 / 20 |
| `#card` 字級／行高 | 14px / 24px |

用**和真實量測完全相同的 `measureInPage()`**（同一個函式被序列化進 renderer）去量，容差 **0**。
2026-11-04 實跑：8 項全中、誤差 0 → 之後印出來的「實測」才有意義。

## 4. 容差為什麼是 ±2px

- `getBoundingClientRect()` 是 CSS px 的浮點數，DSH 自己的 CSS 就用 `.5px` 邊框、`calc()`、`line-height` 取整，subpixel 排版會有 0～1px 的正常抖動。
- 2px 是「同一套設計下肉眼不可分辨、但真正的錯一定抓得到」的界線：248 vs 280（差 32）、44 vs 76（差 32）、104 vs 76（差 28）都遠遠超標。
- 容差不是拿來把錯蓋掉的：**報告照樣印實測值與差**，也不會為了讓某一項變綠而放寬。
- `--selftest` 與圓角代幣固定容差 **0**（代幣是寫死的常數，8px 就是 8px，沒有渲染抖動）。

## 5. 量測環境與「皮膚差異」

- 預設 **`data-shell=dsh` + `data-theme=dsh-light`**：這就是 DSH 參考畫面（真值描述的長相）。
- **每個皮膚的字級／行高本來就不一樣，那是設計不是誤差**：`--theme=boot`（或任何非 dsh／dsh-light 的主題）量到正文紅燈時，報告與 console 會標「皮膚差異，不是版面錯」，`exit 1` 照舊（它真的不符合 DSH 真值）。
- 閘門會先記下「開機原樣」（`env.boot`：`data-shell`／`data-theme`／視窗），再覆寫成量測環境。全新 pref 若沒有 `data-shell=dsh`，console 會印 ⚠ 提醒（殼的 CSS 不會套用）——這是產品問題，量測面只記錄不隱藏。
- 三輪視窗的實際大小會寫進報告 `env.passes[]`（`window` = 真的改了視窗；`emulated` = 退回假 viewport）。
