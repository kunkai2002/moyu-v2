## 2. 為什麼一定要 `--selftest`

量測鏈是 `Electron → puppeteer → getBoundingClientRect / getComputedStyle`。
如果這條鏈自己會偏 1px，那「±2px」就是在量空氣。

`--selftest` 自己產生一張合成頁（`_probe/layout-selftest.html`），裡面是寫死的已知尺寸：

| 已知 | 值 |
|---|---|
| `#w` 寬／高 | 280 × 76 |
| `#brand` 高 | 60 |
| `#icon` | 28 × 28 |
| `#card` 圓角 | 28px |
| `#card` min-height | 36px |
| `#card` padding | 10 / 28 / 0 / 20 |
| `#card` 字級／行高 | 14px / 24px |

用**和真實量測完全相同的 `measureInPage()`**（同一個函式被序列化進 renderer）去量，容差 **0**。
2026-11-04 實跑：8 項全中、誤差 0 → 之後印出來的「實測」才有意義。

## 4. 容差為什麼是 ±2px

- `getBoundingClientRect()` 是 CSS px 的浮點數，DSH 自己的 CSS 就用 `.5px` 邊框、`calc()`、`line-height` 取整，subpixel 排版會有 0～1px 的正常抖動。
- 2px 是「同一套設計下肉眼不可分辨、但真正的錯一定抓得到」的界線：248 vs 280（差 32）、32 vs 38（差 6）、44 vs 76（差 32）都遠遠超標。
- 容差不是拿來把錯蓋掉的：**報告照樣印實測值與差**。2026-11-04 的實例：正文行高實測 **22.68**（真值 24、差 −1.32），±2 之內所以綠，但這其實是 `ui/theme.css:443` 的舊規則 `:root[data-theme="dsh-light"] .p{line-height:1.62}` 蓋掉了 364 行那條 token 規則——報告看得出來，該修。
- 想要更硬就 `--tol=1`（22.68 就會紅）；`--selftest` 與圓角代幣固定容差 **0**（代幣是寫死的常數，8px 就是 8px，沒有渲染抖動）。

## 5. 量測環境（重要）

- 預設 **`data-shell=dsh` + `data-theme=dsh-light`**：這就是 DSH 參考畫面（真值描述的長相）。
- `--theme=boot` 會量「應用程式自己開起來的樣子」：目前 `ui/index.html` 是 `data-theme="claude-code"`，同樣的殼在 CC 皮膚下正文會變 **13.5px / 26.32px**（行高超標 → 紅）。這是**皮膚**差異，不是殼的錯；DSH 殼要長得像 DSH，皮膚就選 dsh／dsh-light。
- 視窗 1440×900 → 不會觸發 DSH 的 1024px 自動收合（側欄 280 才量得到；<1024 時真值是收成 56px 圖示軌）。
